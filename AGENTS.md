# AGENTS.md

This file gives coding agents project-specific context. Keep it short and update it when workflows change.

## Project Overview

- Primary app or package: a pnpm workspace of six packages. `core` holds the role schema and the board; `cli` builds the agent files; `mcp` is the board server; `models` picks the model per role; `adapter-opencode` is the lease guard plugin; `evals` is the safety suite.
- Main entry points: `packages/cli/src/index.ts`, `packages/mcp/src/index.ts`, `packages/adapter-opencode/src/index.ts`
- Important directories: `packages/*` (the workspace), `roles.yaml` (the role source of truth), `openagentsy.models.lock.json` (the generated model assignment), `templates/` (the generated agent files), `.openagentsy/` (board state, leases, audit log)

## Architecture Notes

- Module boundaries: pnpm workspaces (packages/*)
- The board owns the SQLite database. The plugin cannot read it: the OpenCode plugin runtime has no sqlite module, so the board publishes a JSON lease snapshot that the plugin reads.
- Generated or vendored code: `templates/` and `openagentsy.models.lock.json` are generated by `openagentsy build` and `openagentsy models init`. Do not hand-edit them.
- Sensitive areas: the lease guard in `packages/adapter-opencode` decides who may write. The MCP board cannot verify the caller, so a grant trusts the name it is given. The safety suite in `packages/evals` is what proves the guard holds.

## Fallow checks

Use fallow for code-quality, cleanup, and setup tasks in this repository. Fallow checks the changed code before each `git commit` and `git push`. In Claude Code and Codex, a PreToolUse hook from `fallow agent install` runs this check and blocks the command when the verdict is `fail`. Other agents run the check themselves: `fallow audit --format json --quiet --explain --gate-marker agent`. If the verdict is `fail`, fix the reported findings before you try again. A JSON runtime error such as `{ "error": true, ... }` does not block.

Audit defaults to `gate=new-only`: only findings introduced by the current changeset affect the verdict. Inherited findings on touched files are reported under `attribution` and annotated with `introduced: false`, but do not block the commit. Set `[audit] gate = "all"` in `fallow.toml` to gate every finding in changed files.

For non-skill agents, treat the task map below as the local onboarding source: run the listed fallow command before destructive edits, before commits, and before pull request handoff.
